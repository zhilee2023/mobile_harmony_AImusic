# LeVo Harmony / LeVo音乐完整总结

截至2026-11-02。产品为LeVo音乐v1.0.6，研究App为LeVo Harmony v0.1.13，两者与原ACE-Step、CosyVoice项目独立保留。

最新模型表、定期温度／功率采样及公开90秒日志归属审计见[模型与温度总结](MODEL_THERMAL_SUMMARY.md)。旧报告区块保留；公开90秒原任务退出阶段尚未确认。

## 当前结论

公开主Mixed模型已能在手机生成真实混合歌曲；新加入可替换模型包与产品菜单，并用从PT重新导出的VAE完成15秒真实生成和播放。0.6B路线已具备完整数值链路、模型替换和内存验证，但音乐适配器/头及小DiT仍未训练，不能称为已完成0.6B歌曲模型。

小模型90秒完整链路最新两轮RTF1.566/1.608；本轮重构后的30秒新包RTF1.487。公开90秒只有分阶段恢复，6.225是已测LM与Codec时间相加，不是稳定单次端到端。当前默认推理全部为CPU，GPU/NPU未接入产品主线。

## 架构

```mermaid
flowchart LR
  A[歌词和风格] --> B[条件适配与输入表]
  B --> C[自回归音乐 LM]
  C --> D[单路 Mixed 音乐 token]
  D --> E[Codebook与1024维投影]
  E --> F[两步 DiT 分块]
  F --> G[64通道 latent]
  G --> H[共享 VAE]
  H --> I[48kHz双声道混合歌曲]
```

Mixed-only是一条音乐token流，直接合成人声＋伴奏混合音频；不表示只有单声道，也不表示只生成人声。当前省略官方track LM，公开主Mixed LM本身是约3.106B，不应称为完整官方双LM约4B路线。

| 模块 | 公开主Mixed | 0.6B原型 |
|---|---|---|
| LM结构 | Llama接口，36层、hidden2048、FFN11008 | Qwen3学生，26层、hidden1024、FFN3072 |
| LM参数 | 3,106,035,712 | 598,178,304 |
| 音乐输出 | 16384个code＋EOS | 相同输出合同，音乐头未训练 |
| 前缀 | 953位置，已训练歌词/风格等条件 | 512歌词位置＋1风格＋BOS＝514 |
| DiT结构 | 39层、hidden1200、FFN4800、30头 | 22层、hidden1024、FFN2048、16头 |
| DiT参数 | 751,534,224 | 195,416,128 |
| VAE | 84,414,082参数，预训练解码器；当前公开包重新W8/g64量化 | 同一源权重，当前仍用旧W8产物 |
| 当前训练状态 | 主LM、DiT、VAE已训练 | 文本骨干已预训练；音乐适配器及DiT未训练 |

LM输出离散code，经码本/投影后才送入DiT，因此1024/2048的LM hidden不是直接当作DiT hidden使用。替换时仍需匹配词表、特殊token、条件表、码本和归一化，不能只看参数量或文件后缀。

## 分块与生命周期

- code速率25Hz；DiT窗口256帧＝10.24秒，重叠64帧＝2.56秒，hop192帧＝7.68秒。
- 每窗两步Euler、CFG1.5；CFG使用双batch，不能将“两步”理解成没有条件/无条件分支。
- 15/30/90/120秒分别用2/4/12/16个窗口。最后一块仍执行固定形状，重叠和padding会增加计算；90秒的12次VAE前向共处理122.88秒窗口数据，拼接后才是90秒有效PCM。
- VAE输入`[1,64,256]`，输出`[1,2,491520]`，即48kHz双声道10.24秒窗；按有效去重长度计算RTF。
- 当前默认是完整LM生成并释放，再保留唯一DiT与唯一VAE会话解完所有窗口。不反复加载每块模型，也不将整曲浮点PCM累积在内存中。
- 每次歌曲仅首次prefill，之后增量decode保留本次KV。小模型90秒2250新码结束时KV位置2763。不是每块重新prefill全部历史。
- 目前产品是生成完成后播放。Codec分块已实现，token边生成边出声、计算重叠和完整长曲流式仍需单独接入与验证。

| LM外部weight | 1573.71MiB | 236.79MiB |
| DiT外部weight，W8/g64 | 688.76MiB | 211.41MiB |

| 三个外部weight合计 | 2.288GiB | 0.516GiB |

weight合计不包括图、tokenizer、embedding、条件表、运行时packing、激活和KV。公开原19文件基包约3.64GiB；新包增加测试输入/清单，换入g64 VAE外部weight85,861,638字节。不能用ROM大小替代运行内存。

默认LM：公开CPU High4、学生CPU Low4；DiT CPU High请求6；VAE CPU Low请求6＋NEON正弦。Memory Low、Power High，Codec KleidiAI关闭。CPU Low是计算精度偏好，不是4bit量化。没有默认静态A4或KV4，也不应将权重W8理解成全图全部算子都执行INT8。

## 为什么此前小模型VAE看起来更慢

旧90秒VAE95.989秒，在两次重测分别为58.723/59.763秒，原慢速未复现。对第二次整链的12份实际latent，在同HAP新进程独立跑相同VAE，耗时52.406秒，比整链内59.763秒少12.3%；全部窗口原始PCM位模式指纹一致、首窗直接L2=0。

独立进程没有DiT共驻，温度/频率/缓存没锁定，不能将差异全归因于此前运行LM。源码和短线程快照还发现：MNN按CPU mask复用首次线程池，先LM4线程可能限制后续请求6线程；整链看到3个高CPU辅助线程，独立VAE看到5个。请求6不保证实际6，下一轮应先验证最大线程池初始化，再改kernel。

## 当前热点和未完成优化

- 历史VAE热点主要是卷积、转置卷积、激活和布局转换；末级`[1,128,491520]`的FP16单份激活120MiB。参数84M不意味着计算轻。没有DRAM流量/带宽计数，不能直接认定memory-bound。
- W8＋NEON正弦已在默认VAE路径。Snake回调融合曾在独立探针有收益，接入App后较慢，默认保留原入口；没有已验收的VAE三倍或整链三倍加速。
- 公开DiT FFN/QKV已降为Convolution；再次把名字叫Gemm的节点转Conv不会自动再提速。旧热点来自39层公开DiT，不能冒充当前22层小DiT的新热点。
- CANN纯Conv在历史子图测试中更快，完整残差图有CPU/NPU分区与同步，尚无完整VAE或产品整链加速。关闭运行时fallback不会消除OMC预编译CPU子图；旧芯片OMC结果不能直接外推新手机。
- W4 DiT历史上更省ROM但更慢；低bit、CPU Low、更多线程、预加载或重叠均需实际整链验证。

## 换模型与模块化交付

LeVo音乐顶部有“歌曲模型”和“刷新”。原生`models`列出独立模型槽位，`selectModel`切换；生成/导入期间拒绝切换，不存在ID不改变当前选择。默认模型和旧歌曲保留。新模型无需修改编译进去的原权重尺寸，使用各自`model-bundle.json`。

电脑端`modelctl`统一inspect→prepare→pack→verify→deploy，支持PT/PTH/Torch/safetensors、TorchScript、兼容ONNX及MNN。原始权重必须有对应结构；普通HF显式KV ONNX不等于MNN LM输入合同。现成LM ONNX默认统一W8，W4主体/W8头走官方HF/PT导出器。详细命令和边界见[模型部署说明](MODEL_DEPLOYMENT.md)。

真实PT VAE182张量strict通过，ONNX对Torch L2约0.000296%；W8对ONNX7.13%，先被5%门槛拒绝，另以10%兼容预算记录通过，不冒充音质通过。完整小DiT ONNX转换L2约1.64%；TorchScript微型合同及HF音乐头/RoPE小规模适配测试通过。新完整LM仍需逐权重验收。

已验证默认→新包→不存在ID拒绝→恢复新包；新包15秒WAV为720000帧、48kHz、双声道、PCM16，并收到playing/completed播放回调。研究App新包30秒全链也通过。全部结果继续合并到单一JSON，原41个报告区块保留，原始音频/权重/签名不提交Git。

## 下一步顺序

1. 固定同权重/输入，先初始化6线程池，LM仍请求4、Codec请求6，测实际并行、90秒整链与热态重复。当前90秒1.608到1.5还需少约9.71秒；新30秒1.487不能外推90秒。
2. 按prefill/decode区分LM线程与核选择；保留每首KV，评估词表/打包与权重扫描开销。不要把未通过的A4/KV4设成默认。
3. VAE优先消除多余布局与中间读写、使用正确布局的显式融合；NPU继续按连续子图计入同步/边界成本，先证实整模块收益。
4. 在有界共驻和队列背压下接入token到Codec的增量调度；同一任务暂停/恢复LM，避免逐块重复prefill全历史。共驻峰值必须重测，不能将独立峰值直接相加作保证。
5. 公开模型先定位90/120秒长KV/析构退出，再扩大时长。120秒公开High曾捕获至少5.84GiB RSS、最低系统可用866MiB；NORMAL/子码9不足以证明OOM。模型选择重构没有宣称修复它。
6. 取得训练数据与计算资源后训练0.6B音乐适配器/头及小DiT，再做歌词覆盖、衔接和听感验收。
