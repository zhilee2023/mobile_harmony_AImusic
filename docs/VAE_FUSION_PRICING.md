# VAE 融合候选定价

基线是手机上已经执行 36 处 FP16 Snake 融合的 VAE。CMM-AL00 使用 W8/group64 权重，MNN CPU Low、6 线程，每窗 256 latent 帧生成 10.24 秒、48 kHz 双声道 PCM。候选搜索从这条路径实际执行的计算图开始。

## 搜索和定价

1. 采集一遍预热后的 MNN callback。用张量版本关联生产者和消费者，记录后端、形状、实际布局与存储大小。把运行期插入的 Raster 和它的源、目的步长一起纳入图。保留共享张量的全部消费者。
2. 枚举 2–6 个连通节点，同时运行按收益排序的 Beam 和按扩展上界排序的 Beam。候选区域收缩后必须无环。相同拓扑、算子参数和布局的区域归为可复用模板。匹配和布局检查完成后仍需单独验证内核。
3. 对一个位置 `j`，只统计所有消费者都在区域内的中间张量。对每份这样的中间激活，先以省掉一次写入和一次读出计算 `D_j`；如果外部仍要使用该张量，则保留原写入，不计这份收益。按 `t_j` 为原区域 callback 耗时、`B` 为参考拷贝带宽、`f_j` 为目标工作负载中的执行次数，先将 `f_j × min(t_j, D_j/B)` 作为筛选分。这里的 `B=36.4042 GB/s` 来自之前的手机拷贝微基准。图上的存储字节和带宽换算是近似估分，没有读取 DRAM 硬件计数器。
4. 对模板的可用位置求解非重叠集合打包，并检查组合后的图是否仍然无环。无冲突的模板直接合计。按照实际覆盖频次累计运行收益。缩小候选池后，再验证内核生成、数值、工作区和实机速度。

要做预算分配时，对位置 `j` 用 `g_j=f_j(t_j^{old}-t_j^{new})` 作收益。未知的新耗时使用筛选估计，实测完成后才将实测收益交给部署求解。受现有候选竞争的节点可以从受限 LP 得到价格 `π_i`，不重叠的位置集合记为 `A`。一次性开发代价 `d_p` 按实现计一次，`λ` 将开发代价换算成推理时间价值。联合定价使用：

\[
Q(p)=\max_A\left[\sum_{j\in A}\left(g_j-\sum_{i\in S_j}\pi_i\right)-\lambda d_p\right].
\]

此式用于筛选开发候选。最后比较当前整数解与加入候选后的净边际收益，同时应用剩余开发预算、峰值内存和精度限制。本轮只有已部署图的运行证据，新增候选尚无融合后的实测成本。公开榜使用零对偶价格和未扣开发成本的估分。

## 真机结果与当前排序

同一份真实音乐 latent 下，原版与已部署 Snake 融合版 PCM 逐字节一致。独立进程按融合版、原版顺序运行，手机全程亮屏，电池温度 30–32°C。三个无回调预热轮均值为 4.387 秒（模块 RTF 0.428）和 5.668 秒（模块 RTF 0.554）。采样峰值 RSS 分别为 716.28 MiB 和 749.37 MiB，属于包含诊断的进程。该顺序对照仅报告本次观测值。

融合后的回调图为 162 个命令。一次 profile 中普通卷积合计 2591.32 ms，转置卷积 981.93 ms，Snake 652.52 ms，Raster 171.29 ms，逐点 BinaryOp 56.79 ms。卷积与转置卷积占累计回调时间约 80%。

低开发成本的首测目标是 `Snake → Raster → Conv` 边界。运行图有 31 个 Raster，都是零偏移、同布局、同存储大小、完整连续拷贝，累计回调 **80.12 ms/窗**。这一数字是既有拷贝时间。直接复用存储还需验证 MNN 的别名语义、缓冲区寿命和 PCM。大幅缩短整窗时间还需要单独测量卷积和转置卷积的具体实现。

## 复现

`levo_stream_vae_fusion BUNDLE LATENT OUTPUT fused --profile` 在当前已融合路径完成四次无回调运行，再记录一轮张量依赖和算子耗时，验证 PCM 与预热结果一致。`baseline --profile` 用相同输入运行原版。离线定价读取同一目录的 `profile.json` 和 `result.json`，以及原图的 MiniReflect JSON：

```text
python tools/price_vae_fusions.py PROFILE RESULT SOURCE_GRAPH OUTPUT --bandwidth-gbps 36.4042
```

发生位置冲突时，求解使用本项目已有的 CPLEX 集合打包。统一报告条目为 `vaeRuntimeFusionPricing20261125`。

## 按实现动作给候选定价

把子图搜索与实际改写分开。原始逻辑流量估分仍用于发现子图。对于仅消除 Raster 的实现，单独识别将要改写的 Raster，先核对输入输出具有相同 FP16 C8 存储、零偏移、完整连续映射和实际消费者，再累计实测拷贝时间。卷积、Snake 和残差 Add 继续执行原内核，它们的中间结果不计入这个实现的预计收益。同一批 Raster 即使出现在不同大小的候选子图中，也只进入一次开发计划。

\[
T_{\mathrm{copy,est}}(p)=\sum_{r\in R_p}f_r T_{\mathrm{Raster,old}}(r).
\]

此估分来自原图的回调，仍需用实测的 `old−alias` 复核。跨候选应用时还要考虑别名会改变中间张量的生命周期。局部回调省时可以独立估计，部署选择要看整窗配对时间、数值和峰值占用。两者在报告中单列。

独立 `levo_stream_vae_alias` 实验只在 MNN 内存分配前替换白名单中的完整 Raster。目标张量保留原形状，复用源张量的存储引用直到视图最后一次使用。运行时仍核对每次改写确实发生。`tools/run_vae_alias_benchmark.py` 可按旧榜排名复测，逐个保存无回调预热时间和一轮 Raster 回调时间。数值对照用同一份完整 PCM 的 SHA-256。

### 真机配对结果

旧榜十项均完成，每项实际消除 4–9 次 Raster，十次的 PCM 均与六组控制逐字节一致。设备与窗口规格同前。每次独立加载同一个 VAE，首轮用于预热，取两个无回调窗口的耗时中位数，并额外采一轮 callback。每两个候选前后插入控制，按运行顺序插值；局部与整窗均比较相邻控制。全程亮屏，电池温度 30–39°C。

按实际改写去重得到八种计划，以局部 Raster 节省为比较目标，原子图估分和动作级估分的平均绝对偏差分别是 **15.56 ms** 和 **5.82 ms**。动作级价格来自上一次独立的真机 profile，未用这轮候选结果回填。新版脚本同时输出旧 Top 10 的动作级重排和全候选重排，保留原子图估分供结构发现。统一报告条目为 `vaeRasterAliasValidation20261125`。
