# VAE 的算子图与执行原语定价

全局层以 VAE 已部署的 MNN 执行图为输入。每个位置保留算子、Tensor 依赖、消费者、观测到的首次产生与最后消费、实际存储大小及布局。局部层将一个算子展开为读、写、Packing、Layout、计算与同步。Tensor ID 标识执行中的张量版本，底层存储别名仍由具体改写及内存计划验证。

`tools/build_vae_primitive_graph.py` 从真实的 162 命令图导出两层结构。Raster 的区域映射和 FP16 Snake 具备运行证据。卷积结构包含形状、膨胀率及权重量化元数据。`tools/build_vae_executor_probe.py` 用原 MNN 构建参数编译独立执行器探针，记录转置卷积分段和实际申请的 scratch 大小。启用 `--with-convolution` 后，也记录 W8 路径的动态激活量化、Pack A / Im2Col 和 GEMM epilogue。两个工具均为离线或独立 CLI 实验。

## 局部实现定价

将一个候选写成区域、重写规则、实现参数和部署位置。原始收益只对实现实际改变的阶段求差，共享消费者需要的完整输出仍保留。消拷贝的第一版用实测 Raster 回调作估计。`Snake → Conv` 的分块实现如果产生 Halo 则要计入重复计算。普通卷积输出 tile 为 `b`，输入跨度为 `(b−1)·stride+dilation·(K−1)+1`。合法性还取决于边界填充、布局、量化语义和活动缓冲区寿命。

对串行阶段集合 `H`，一个可校准的时间模型为

\[
\hat T=\sum_{h\in H}(C_h+M_h-\rho_h\min(C_h,M_h)+S_h).
\]

`C` 记录实际用到的微内核，包括计算、特殊函数和 shuffle。`M` 按材料化和生命周期记录逻辑读写，只有取得相应的计数或校准后才估算各级 Cache 和 DRAM 流量。`S` 记录固定调度成本。Packing 已计入 `M` 的字节不再加到 `C`。嵌套和多线程区间使用阶段墙钟及各 worker 样本，不能把不同 worker 的耗时相加冒充推理耗时。经验有效吞吐量用于预测和软筛选。只有能覆盖所有允许实现的有效下界才用于安全剪枝。

## 全局部署与开发预算

对于实现 `k=(pattern, rewrite, parameters)` 和一组相容位置 `A`，生成列 `(k,A)`。部署 Master 约束包括算子覆盖、列收缩后无环和边界接口兼容。内存用选中组合的活跃存储与 workspace 检查峰值。局部 PCM 误差通过后仍需要整链验证。多个位置共享同一份代码，开发成本按实现只收一次。允许同一个拓扑有几种互补实现时，唯一性行应用于实现 `k`。只有策略明确限制每个拓扑一种实现时，才使用拓扑约束。

若离线目标同时包含固定开发惩罚 `η` 和开发预算，节点、预算、实现唯一性的 LP 对偶分别记为 `π`、`μ`、`σ`。在每列代表一个实现的放置集合时，它的约化收益为

\[
\overline G_{k,A}=\sum_{j\in A}\left[f_j(T_j^{old}-\hat T_j^{new})-\sum_{i\in S_j}\pi_i\right]
                  -(\eta+\mu)d_k-\sigma_k.
\]

`η` 是外部开发成本权重，`μ` 由预算行产生。在线 Master 使用已验收实现的实测值。新实现的估计只进开发的候选队列。若运行层的延迟改善在复测误差内，局部原语即使显著更快也不进入部署解。当前 Raster 实验正好需要这个限制。

## CMM-AL00 单窗执行器实测

同一个 256 帧真实 latent、W8/group64 权重、CPU Low 6 线程、已融合 Snake。使用 `levo_stream_vae_fusion` 的仪器化副本，参数 `fused --once`。探针只跑一窗，按算子顺序和形状将 32 个普通卷积、5 个转置卷积与原 162 命令图逐一对齐。PCM 与独立非插桩基线逐字节一致。时间用于代价标定和热点定位，插桩后的总耗时不参与提速验收。

32 个普通卷积都进入 `DenseConvInt8TiledExecutor` 的 W8、动态 A8 路径，输入和输出是 FP16。17 个先 Im2Col，再按该分支动态量化，15 个先动态量化，再打包。该样本没有观测到独立输出量化或在线重排权重的调用。

5 个转置卷积都执行 FP16 GEMM 并用 4 个 worker。第一个直接累加到主输出，其余三个各用完整临时输出。最大层申请约 360.06 MiB 局部 scratch，和另外 120 MiB 主输出分别计算。这些是分配参数，各层顺序执行，不能把 5 层 workspace 加总为进程峰值。末级的最慢 worker 的 Col2Im 约 64.84 ms。带相同边界的下一步定价可以分别评估输出 tile 归属和融合 Reduce/Bias。前者需计入 Halo 和 FP16 加法顺序，后者的收益估计只能覆盖归约和 Bias 阶段。

普通卷积的首轮候选需要分别量化 Pack-first 与 A8-first 两个执行器分支的收益。转置卷积的峰值内存定价优先考虑缩小每线程完整输出。同一笔流量只归入一个原语。具体改写和收益尚需测量，当前数据用于候选生成。统一报告条目 `vaePrimitiveExecutorTrace20261125`。

## 温度记录

旧十项连测的电池温度从 30°C 升到 39°C。另一次冷却后控制组从电池 32°C、背部 34.00°C、板级 33.72°C 启动。该轮背部峰值 35.47°C、板级峰值 42.66°C，电池仍为 32°C。由于背部在冷却期间没有及时回落到 35°C，计划的四轮配对只完成这一控制组，不作为消拷贝提速验收。

随后执行器探针只跑一窗。电池仍为 32°C，背部传感器从 34.90°C 到峰值 35.79°C，板级传感器从 34.54°C 到峰值 39.83°C。为这些实验观测的系统传感器读数。

## 2026-11-26 转置卷积归约与 Bias 单遍融合

独立探针在 FP16 C8、四个 worker 和 Bias 系数为 1 时启用单遍 NEON 实现。每个向量按原顺序累加三个线程的部分输出，再加 Bias 并做 Clamp，最后写入一次。各次加法保留 FP16 舍入。原 VAE 配方仍是已融合 Snake、CPU Low、请求 6 线程，每窗输出 10.24 秒音频。

在 CMM-AL00 上用同一个二进制和固定真实 latent 跑四对，顺序为原版→融合、融合→原版、融合→原版、原版→融合。每次独立加载，计时覆盖单窗执行和 PCM 拷贝。五层都核对了实际执行的分支，八次输出与既有 PCM 参考逐字节一致。

| ---: | ---: | ---: |
| 2560 | 0.67 ms | 0.62 ms |
| 15360 | 2.12 ms | 2.05 ms |
| 61440 | 4.74 ms | 4.18 ms |
| 245760 | 13.42 ms | 8.11 ms |

末段配对省时为 22.28、21.66、20.18 和 19.75 ms，中位数 20.92 ms。整窗中位数为 4.483→4.475 秒，配对差从慢 246.38 ms 到快 230.15 ms。此样本支持末段提速约 40%，整窗加速仍待更高重复次数验证。两组峰值 RSS 都约 716 MiB，末层仍需 360 MiB 的线程私有累加缓冲。

初始电池、背部和板级传感器分别为 25.0、27.34 和 27.22°C，采样峰值分别为 27.0、32.66 和 42.76°C。每对开始前读取温度，达到实验暂停条件时允许冷却。该轮四对均在亮屏状态执行。

### 用实测修正收益估计

把末段的三次独立归约和一次 Bias/Clamp 改成单遍，每个输出元素的逻辑访问数从 11 降到 5，忽略小且重复使用的 Bias 向量。直接按 `6/11 × 旧阶段耗时` 估算可省 29.37 ms，较四对实测中位数高 8.45 ms。该比值描述逻辑访存，原循环的缓存复用和新循环的多路读取会影响耗时。

只用前两对校准这一动作，取实测平均省时除以前一轮的 29.37 ms，得到系数 0.748。后两对的局部预测平均绝对误差从 9.40 ms 降到 2.01 ms。该系数来自同机型、同输入和同一实现的小样本，可作为此动作的经验定价。使用其他布局、工作集或线程数时需重新采样。

复现时给 `tools/build_vae_executor_probe.py` 增加 `--epilogue-comparison`，在设备执行 `vae-executor-profile BUNDLE_ROOT LATENT OUTPUT_DIR fused --once`，分别设置 `LEVO_VAE_REDUCE_BIAS=0` 和 `LEVO_VAE_REDUCE_BIAS=1`。日志中的 `LEVO_VAE_EPILOGUE_SETUP` 记录分支，`LEVO_VAE_EPILOGUE_PHASES` 记录每层两阶段墙钟的纳秒值。统一报告条目为 `vaeDeconvolutionEpilogue20261126`。

## 完整 VAE 组合与 Phase 0–2 首轮校准

`tools/select_vae_combination.py` 对八种去重后的 Raster 改写和一个归约融合方案求解 CPLEX 集合打包。同一执行位置最多由一个方案覆盖。局部省时使用前一轮配对实测。LP 松弛和整数解的目标均为 117.55 ms。选中的两个 Raster 方案共覆盖 18 处拷贝，加上五层转置卷积归约融合。

`tools/build_vae_executor_probe.py --epilogue-comparison --layout-alias` 可将两类改写链接到同一个探针。对照采用部署版 Snake，试验组在其上启用选中的 18 处消拷贝和五层归约融合。CMM-AL00 每次加载后预热一窗，记录第二窗的执行及输出拷贝，共三个交错配对。256 latent 帧对应 10.24 秒输出。六次 PCM 与既有参考逐字节相同。

| 整窗指标 | 部署版 Snake | CPLEX 组合 |
| --- | ---: | ---: |
| 中位数 | 4.307 s | 4.919 s |
| VAE RTF | 0.421 | 0.480 |
| 进程峰值 RSS | 718.50 MiB | 686.50 MiB |

按对计算的整窗省时为 −979、+5、−352 ms。首轮从电池 27°C、背部 29.10°C 开始，三个配对中背部峰值 36.06°C、板级峰值 46.30°C。相反顺序的配对最接近持平，本轮无法分离温度、顺序与改写的效应。`tools/summarize_vae_pairs.py` 输出中位数、样本 P95、配对差和探索性 bootstrap 区间。三对样本仍处于测量试点阶段，尚不足以判定 50 ms 量级的变化。

构建并执行 `vae_copy_calibration` 得到 Phase 2 的首组连续复制样本。每个工作集预热一次，取后五次中位数，按源和目标的逻辑读写总量计费。六线程在工作集 48 KiB、12 MiB、96 MiB、288 MiB 处分别测得 163.72、123.17、21.41、29.81 GB/s。复制样本可用于分工作集初始估价，缓存层级仍待计数器或单独的缓存探针验证。采样的 CPU 频率来自探针前后四个 cpufreq policy。执行器内部的 Packing、Scatter 与 GEMM 仍分别使用已采集的原语计时。

统一报告条目为 `vaeFullCombinationPilot20261126`，包含配对结果和十个复制样本。

## 按物理存储重放 VAE 执行图

算子依赖沿用原张量 ID。可安全消拷贝的 Raster 另外记录源张量和目标张量。求解某个组合后，`tools/vae_storage_graph.py` 将二者归到同一存储组，按最早产生和最晚消费计算存活区间，并在转置卷积执行点加上实测分配的 scratch。该轨迹覆盖观测图里的张量和有测量依据的 scratch，进程 RSS 还包含其他内核的临时区、参数和分配器持有的内存。

原图有 163 个可见存储组，18 处 Raster 改写将其降到 145 个。其中 9 个执行点各少同时持有 60 MiB，另 9 个执行点各少 120 MiB。全图最高的建模占用出现在末级转置卷积，由 180 MiB 活跃张量与 360.06 MiB scratch 构成。两条路径在该点的建模峰值均为 **540.06 MiB**。前一轮真机 RSS 的峰值差额另见配对结果。

`tools/select_vae_combination.py` 支持 `--primitive-graph` 和 `--max-modeled-peak-mib`。先解只含互斥约束的 LP 和 MILP。再重放整数解的存储轨迹，超限则添加排除该具体组合的约束并重求。以当前 9 个候选回放，550 MiB 上限保留原组合，530 MiB 上限排除了全部 32 个满足互斥约束的组合。峰值约束让临时区成为独立的优化目标。延迟收益仍基于局部计时，已有真机整窗结果用于核验排序。
