# 长歌词实机测试：0.6B四分钟与较大模型两分钟

2026-11-24，CMM-AL00，MNN ARM CPU，LLM 4线程、DiT／VAE各6线程；20ms采样进程RSS。
长歌词为新写的48行／318-token样例，固定513位置prefill；MuQ风格NPY，DiT两步Euler＋CFG1.5。
固定长度测试屏蔽提前EOS；停止按钮与6GiB RSS／650MiB系统余量保护保持有效。

## 0.6B：完整240秒

v0.1.12，28层／H1024音乐LLM、22层DiT、融合VAE，三个模型共驻、串行计算，无token预取。
原计划冷却6分钟，在添加长歌词入口期间实际推理前准备空闲超过8分钟，没有启动原短歌词240秒任务。

含条件文件和当前额外输入embedding的实际部署ROM **1.384 GiB**，排除歌曲、日志和HAP。
量化：LLM主体W4/group64、头W8、分组动态A8；DiT W8/group64；VAE W8/group64、CPU Low FP16、每窗36处Snake融合。
阶段RAM为该阶段整个进程的RSS，包含其他共驻模块，不可相加，也不是独占模块RAM或GPU显存。

## 较大模型：完整120秒

按手机现有`larkstudio-base-v2`，界面标为4B：36层／H2560音乐LLM＋39层／H1200 DiT＋VAE。
不把另一套未提供的“5B权重”当作已部署资产。上轮结束后观察冷却420.225秒，再测长歌词120秒。
采用原配方：LLM W4/group64、头W8、默认动态A8；DiT W8、两步＋CFG；VAE W8／CPU Low，无小模型专用融合。
LLM保持至任务结束，DiT／投影／VAE按阶段创建和释放，不创建第二套隐藏模型池。

较大模型的完整ROM含conditioner约752.80 MiB，包内22个资产逐一核对尺寸和SHA256。
DiT加载／创建累计29.78秒、VAE累计30.71秒，均已包含在各自阶段耗时，不重复加到总计。
它与小模型共驻策略不同，不能把整链速度差只归因于参数量。

|---|---:|

较大模型使用consume对齐：采样后把当前code输入LLM，取得该code的最后层hidden并投影给DiT，
所以3000个code对应3000次decode，最终KV3513；小模型本轮6000个code则为prefill采样首个code＋5999次decode，条件通过token查表取得。

16个WAV合计完整120秒／48kHz双声道，首块64.05秒；播放到120秒，无错误事件、未提前EOS。
196次前台采样全部FOREGROUND，无息屏记录；电池35→41°C，最低系统可用内存1647 MiB。
本轮符合脚本前台／时长验收条件。两轮都未达到6GiB RAM门槛，但起始温度、时长及模型驻留方式不同。
