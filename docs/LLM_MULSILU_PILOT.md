# 第一轮MUL_SILU候选与频率感知规划

2026-11-24，CMM-AL00，CPU High／4线程。保留原MNN、权重和音乐App；所有候选为独立二进制。

## 候选与质量验收

这是已有SiLU＋Multiply算子内部的cache blocking，不是新图融合，也不是真正寄存器融合。沿用原MNN SiLU和乘法函数，改变分块大小；原MNN线程划分不变。FP16或输出与输入重叠时回退原实现。
真实第一层MLP prefill／decode输入及输出只在私有目录保存。5个生成版本均成功编译：tile0为原样重编译控制，4档为候选。6种二进制共18个独立进程，次序按seed42/43/44打乱，每档3轮。每进程先执行3次，再取25次中位数。全部真实输出全量L2=0。

## 更新后的cost

诊断每次forward有28个门控位置；目标工作量有1次prefill和64次decode，分别28次与1792次。原诊断仅2次decode，先除以2再外推，不直接把56乘64。这里只对形状不随KV增长的门控做显式外推，不能照搬到Attention。
当前回调代理cost：prefill 24.513 ms＋decode 8.520 ms＝33.033 ms。
它只占原固定LLM工作量约1%；因此单点快6%对应的整模型收益估计远小于1%。回调不是严格wall-time分解，不能将此当作已证实上界。

频率感知模型在所给估计表里选择['tile4096']，而非单次prefill表里的tile256。每个实现y只计1次开发，28个位置x复用；64次decode已计入成本，不再重复相乘。
这仍是代理预测：额外整图开销未知，不产生部署许可。回顾性开发预算1只是算法演示；实际5个版本已编译，当前复用时新增开发成本为0，不能再次扣费。

实际接受路线仍是stock。下一轮应优先研究占比更高的量化Linear／Attention，以及同上下文的kernel／调度测量。简单Roofline中各tile的总逻辑IO相同，不能解释缓存局部性差异；需要分层缓存／packing／dispatch特征。
