# 连续5块与RTF1.5目标验证（2026-10-29）

v0.1.5签名App在Mate 80 Pro上实际完成一次连续5块流程；不是单块耗时乘五。

## 连续性与有界内存

LLM仅加载/执行prefill一次，之后保留同一KV。DiT和VAE各创建唯一会话，全部共驻，CPU依次计算。首块需要256个新音乐码，后续每块新增192码、复用64码上下文，共1024码。KV逐块为769、961、1153、1345、1537位置，跨DiT/VAE暂停后继续decode，没有每块重新prefill。

DiT仍为完整39层W8、每块两步、CFG1.5。后续块以前一块归一化latent的64帧尾部作context，按官方Euler上下文混合方程更新，最终恢复已知前缀。VAE只保留当前PCM窗口和64帧PCM尾部，交叉渐变后丢弃已发出数据，不积累完整歌曲PCM。这里的“发出”是数值sink，未播放或写出可听歌曲。

每块10.24秒，四个衔接各重叠2.56秒，所以有效时长是`5×10.24−4×2.56=40.96秒`。前四次各提交7.68秒，最后提交10.24秒，所有输出有限。

## 为什么当前还不到1.5

1.5对应40.96秒输出最多61.44秒计算，较113.11秒还需减少约46%。固定其余阶段时，即使DiT耗时降为零，仍约75.09秒、RTF1.83，因此不能只靠DiT FFN或MatMul→Conv达到目标。需要同时加速VAE和LLM，或验证真正有效的异构流水。所有阶段当前仍在CPU顺序计算。

首块之前的初始化虽只做一次，但重叠区仍需重新计算；KV增长也增加后续注意力读写，所以长文本不会自动摊薄到实时。用户当前允许随机音乐头，只验证流程，但不因此降低步数/时长口径或把推测写成成绩。

## 本轮优化尝试

- 完整DiT CPU Low独立探针输出有限，单次回调墙钟约2.998秒；同量化PC参考L2约3.25%，仍非严格1%对齐。这个结果不能直接当作整链提速。
- 增加`chunks-5-tuned`候选：DiT Low、VAE8线程、LLM Power High，保持原W8模型、两步、CFG1.5及40.96秒口径。首轮观察器超时后原PID40681仍存活，电源SLEEP；用户恢复前台后，同一任务完成。其1038.20秒/RTF25.35包含长暂停，不参与速度排名，没有扣除未知暂停时间。
- 原任务确认终止后，用户保持前台，以新ID进行第二轮：**141.041秒，RTF3.443，峰值2266MiB**，1024码、KV1537、5块均完成。DiT合计46.604秒、VAE60.364秒，均比基线慢，因此不启用该组合。结束观察电源AWAKE，仍没有连续温度控制。
- 同一原生CLI程序单独比较LLM的本地`cosyvoice_kleidiai`开关，模型/514前缀/256输出码相同：关闭prefill2.756秒、decode55.40 token/s；开启2.231秒、52.90 token/s，没有decode收益。该开关来自本机MNN已有补丁，库中已编译KleidiAI且默认关闭；不能据此声称所有层实际选择了KleidiAI，更不能把CLI成绩当App整链。旧自定义W8A8 FFN核仍未移植。
- 通用MNN Transformer/C4融合转换在优化阶段失败；关闭C4、只启用Transformer融合的隔离子进程退出码3221226505（0xC0000409），未产出模型。该选项未启用到默认生成路径。失败日志和退出状态进入统一报告，不声称FlashAttention或融合已生效。

此前手动Kleidi W8A8/NEON i8mm FFN迁移方向仍成立，但尚未完成新1200/4800维度接入；见KERNEL_REUSE_REVIEW.md。

## 复现与限制

`tools/run_signed_chain.ps1 -Policy chunks-5 -RunId 唯一ID`触发签名App后台测试；优化候选为`chunks-5-tuned`。观察超时只结束观察器，须检查原App PID和`three-module/last-chain-progress.jsonl`，不要自动重新起跑。保持手机亮屏和LeVo前台。

`tools/merge_five_chunk_validation.py`核验五块码数、KV长度、有效PCM计数、模型会话复用和RTF分母，追加统一报告`five_chunk_validation_2026_10_29`。每轮包/源代码哈希保存在本地receipt并收录报告；基线签名HAP留在忽略的dist本机目录，签名/权重不发布。

原PID40681已完成，无需继续等待或恢复。后续独立CLI探针会覆盖通用last-chain-progress文件，判断App任务须同时核对运行ID、进程与报告，不能只依据该文件存在。

仍是未训练音乐/style适配器及未恢复训练的裁剪骨干，严格跨平台数值门槛也未通过。有限PCM和流式内存测试不能作为真实歌曲生成或音质证明。本轮没有证明RTF1.5可达，未验证4000码或无限时长。
