# LeVo Harmony：120秒公开模型与0.6B原型测试

2026-11-02，同一台手机，分别冷启动LeVo Harmony运行小模型和公开模型。小模型用v0.1.9，公开模型重测用v0.1.10（增加退出记录、中途峰值保存和诊断时限），因此不是同一签名HAP；保留各自哈希和配置，不把差异当作严格模型尺寸消融。两包使用同一MNN静态库，SHA256为`fbaa87b8cae9cd451560803ee3837886fe7e44d48976fc12654654412226159c`。

每轮固定生成3000个新音乐code，对应120秒；LLM仅第一次prefill，随后增量decode并保留本轮KV，生成完销毁LLM。再加载唯一DiT与唯一VAE，会话连续复用16窗，无跨窗重新加载模型。正式重测隔离其他音乐生成进程，没有启用GPU或NPU推理。

为了保证跑满120秒，测速入口抑制EOS；正常LeVo音乐App仍尊重EOS。公开路径使用真实已训练权重输出歌曲WAV，但强制长度、歌词覆盖、段落结构和音质没有听感验收。0.6B音乐头及小DiT未训练，只验证有限值PCM和部署成本，输出写入`/dev/null`，不冒充真实歌曲。

这些位宽指可量化权重的存储目标，不代表全图所有常量或实际kernel都使用相同位宽。公开/小模型LLM外部权重文件分别1650155246/248296682字节，DiT分别722214236/221684024字节，共用VAE为84569334字节；不包含embedding、条件表、运行时packing、激活和KV，不能据此直接当作内存峰值。

采样：seed2307、topK50、temperature0.9、最近50个code重复惩罚1.1。DiT每窗256帧/10.24秒、重叠64帧/2.56秒、步进192帧/7.68秒；16窗共32次两步CFG前向，最后一窗仅120帧有效。VAE每次仍计算256帧，拼接后有效长度120秒，48kHz双声道PCM16。不会为120秒创建一张长DiT图，也不累积整曲浮点PCM。

## 实测耗时

阶段RTF＝该阶段墙钟秒数/120。LLM包括加载、prefill、decode、采样和释放；prefill/decode两行是其子项，不重复计入合计。DiT/VAE为实际前向与同步；其他包括条件处理、Codec加载和PCM拼接输出。全部为带内存采样的实际App运行，不是模块速度外推。

|案例|结果|耗时|RTF|前台口径|
|---|---|---:|---:|---|
|小模型120秒|3000码和120秒数值PCM完成|234.854s|1.957|旧轮缺少前台轮询，不能当严格前台基线|
|公开Codec独立120秒|16窗完成，2725真实码＋275重复夹具码|196.363s|1.636（仅Codec）|每3秒前台检查通过|
|公开High第一次|2725/3000码检查点后退出|记录到548.348s|无完整RTF|未完成前台归档|
|公开High隔离重测|2450/3000码检查点后退出|记录到471.653s|无完整RTF|未完成前台归档|
|公开High前台重测|2725/3000码检查点后退出|记录到569.022s|无完整RTF|至退出前没有前台检查告警|
|公开Low|加载阶段Arm82零尺寸缓冲断言，SIGABRT|约7秒进程生命周期|不适用|崩溃时为前台|

公开独立Codec前向：DiT103.682s、VAE90.984s，其余1.697s。夹具重复部分仅用于容量/性能负载，未输出歌曲，不代表完整3000码自回归生成。

## 内存与图形内存

|指标|数值|
|---|---:|
|小模型旧120秒RSS峰值|1128.71MiB|
|小模型旧120秒PSS峰值|1068.85MiB|
|公开独立Codec RSS峰值|1630.30MiB|
|公开High前台重测检查点捕获RSS|至少5978.62MiB＝5.84GiB，完整峰值未知|
|公开High前台重测最低系统可用|866MiB|
|图形内存API|小模型完整旧轮、公开Codec均读0KiB；退出LM的完整峰值未保存|

阶段即时RSS曾只有约4GiB；独立采样发现更高瞬时峰值。NORMAL/子码9和空消息不够判定OOM。CPU Low的失败有明确`CPUBackend::allocBuffer(size=0)`断言栈，不能作为可用recipe。

RSS每20ms独立采样；HiDebug PSS查询在线程中执行，每次查询后等待500ms，图形API每两次查询一次，实际周期受查询耗时影响。跨阶段的慢查询只保留全局峰值，不错误分给某一阶段。PSS是HiDebug的Pss+SwapPss口径，不能与RSS相加或把大于RSS解释成错误。图形内存API是App归属指标，不是整机GPU使用量。两条推理链均用CPU，RSS/PSS属于共享物理内存，不能叫独立显存。

采样查询可能扰动耗时和漏掉短峰值；后台查询累计时间包含等待，不能从整链墙钟扣除。保持前台亮屏并核对测试前后无息屏；未控制温度、系统调度和文件缓存。公开模型附带只读CPU频率与`soc_thermal`观测，观测从LLM阶段中途开始，不能作为全程峰值或小模型对照。

## 与30秒结果的关系

此前30秒对照在v0.1.8完成，详见[原表](CHAIN_COMPARISON.md)。本轮改为独立RSS采样线程，固定120秒还抑制EOS，因此时长之外并非所有条件完全一致。单轮比值只能描述现象，不能当作严格“只改时长”的提速消融。

小模型120秒旧轮RTF1.957高于旧30秒1.472；但旧轮没有全程前台检查，温度、调度、采样策略也未锁定，不能得出严格时长消融结论。公开模型没有完整120秒端到端RTF，不能相加失败LM时间和独立Codec时间来制造总成绩。用户随后改为90秒，结果及分阶段恢复说明见[90秒记录](CHAIN_COMPARISON_90S.md)。
